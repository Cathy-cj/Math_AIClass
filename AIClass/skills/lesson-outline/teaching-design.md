# 备课方法论（teaching-design）

**lesson-outline（备课）与 fill-lesson-plan（上课）共同必读。**

一个只把【详解】复述一遍的讲法是 20 分老师。90 分老师在**备课**时就设计好：这道题为什么值得学、学生会卡在哪、从哪切入、每一轮推导在干什么、在哪个认知关口抛出什么互动题、最后让学生带走什么。这些设计全部落在 `outline.json` 的结构化字段里（备课产物），fill 阶段只负责把设计**说出来**（上课产物），不得临场另起炉灶。

**备课是全流程中投入思考最多、耗时最长的一步。** 宁可在 outline 上多花几倍的时间与 token，也不要让 fill 阶段拿着单薄的设计去凑课——outline 没想透的「为什么」，plan 里只会变成答案复述。

## 一、开场定位（30 秒）——`positioning`

上来**不讲题**。先用约 30 秒告诉学生这道题的**代表性、整体性、普遍性**：

| 字段 | 写什么 | 示例（三角形翻滚题） |
|------|--------|----------------------|
| `represents` | 代表性：本题代表哪类题、在单元/题型谱系中的位置 | 「弧长」和「周期」第一次同台，本单元与找规律板块的跨界题 |
| `generalSkill` | 普遍性：学会它带走什么通用方法、以后哪里还会用 | 从重复里找周期——到初中仍是主角的能力 |
| `examRelevance` | 可选：真题/考试背景 | 小升初最爱考的跨界题型 |
| `hook` | 开场悬念一句：把学生的眼睛引到正确的第一眼上 | 题目往这儿一放，先看它给了什么、又要你什么 |

- 定位必须**具体到本题**，禁止空话（「这道题很重要」不合格）。
- fill 阶段开场（`group: 0`）就用这四项组织口播，配 phrase-bank 变化措辞；**不得逐字照抄任何范例原句**（见 phrase-bank `banned`）。

## 二、解题主循环——五步

课堂主体永远按这条循环走，对应 `teachingStages[]` 的**固定骨架**：

```text
审题环节 → 从哪入手 → 推导环节 ×N → 提取已知 → 列式计算
(read-problem)  (entry-point)   (题目专属命名)   (extract-knowns)  (compute)
```

### 1. 审题（read-problem）——很多学生错在审题不仔细

- 已知逐条揭示（problemBrief 快照，已有约定）。
- **禁止设计 `interactions[]`**：审题只做读题与条件揭示，互动从「从哪入手」及后续环节开始（硬契约见 [reference.md](../lesson-plan/reference.md)「审题环节禁止互动」）。
- **问句里的陷阱必须点名**：「问的不是硬币滚了多远，是圆心走了多长——一字之差」。条件越短的题越要提醒「信息全埋在×字里」。审题陷阱写在 read-problem 环节的 `trap` 字段。
- 审题结尾三连：要用的知识预告（口播可说，屏幕不展示）→ 范式级主攻方向（`entryPoint.strategy` 的预告版，如「化整为零」）→ 难度播报（全题星级，配 phrase-bank `difficulty.report`）。

### 2. 切入点（entry-point）——备课时花最多思考的地方

很多学生不是不会算，而是**不知道从哪开始**。备课时必须把切入点想透，写进 `entryPoint`：

| 字段 | 写什么 |
|------|--------|
| `stuckPoint` | 学生拿到题为什么会卡住、卡在哪 |
| `observe` | 高手第一眼观察什么（运动路径？重复结构？图形关系？） |
| `strategy` | **解题思维范式**（4–12 字口诀），可迁移到同类题；学生能复述「从什么角度切题」 |
| `rejectedPaths` | 可选：排除的死路及原因（「翻滚 30 次不能逐次硬算——所以要找周期」），排除死路本身就是教切入点 |

**三层分工——别把操作步骤写进 strategy**：

| 层级 | 字段 | 抽象度 | 合格 | 不合格 |
|------|------|--------|------|--------|
| 范式 | `entryPoint.strategy` | 可迁移到同类题 | 化整为零、找周期规律、化未知为已知、换视角看圆心 | 拆分两块再相加、先算阴影占比再加 |
| 略具体 | `problemBrief.key`（可选） | 本题防坑一句 | 阴影＝整图−空白、共用底面积别漏 | 先分别求两段体积再相加（操作链，宜进推导） |
| 操作 | 推导 `approach` / `loop` | 本题逐步 | 分别求上下段体积 → 相加 | — |

**范式 vs 操作正反例**（阴影面积题）：

- ✗ strategy：「拆分两块，分别占几分之几，再相加」——这是操作路径，应写在第一个推导环节的 `approach` / `loop`
- ✓ strategy：「化整为零」或「阴影＝整减空」——学生带走的是切入角度，具体怎么拆、怎么算占比在推导环节展开

archetype 常见范式（启发，非模板；详见 [phase-routing.md](../lesson-plan/phase-routing.md)）：`compositeSplit` → 化整为零；`patternCycle` → 先找周期 / 看重复结构；`relationBridge` → 化未知为已知 / 搭等量桥；`directFormula` → 对号入座 / 公式直代。范式须贴本题（周期题写「先看懂一次，再数周期」优于空泛「找规律」），但**不得**写列式顺序。

`teachingStages[]` 第二项固定为 `entry-point / 从哪入手`，通常 1 步：口播用 `stuckPoint` / `observe` / `rejectedPaths` 展开「为什么选这个范式」；**具体操作链**从第一个推导环节开始，不在 entry-point 重复。

### 3. 推导环节——每一环节就是一轮「已知 → 未知」

找到切入点后，从已知条件求出解题需要的未知量。每个推导环节写 `loop` 字段声明这一轮推导：

```json
"loop": { "from": ["等边三角形内角 60°", "地面平角 180°"], "get": "每次旋转 120°，A 走一段 120° 弧" }
```

- **逻辑链短**（一轮推导出答案）→ 1 个推导环节；**逻辑链长** → 多个推导环节串联，上一轮的 `get` 进入下一轮的 `from`，直到能算出最终答案。环节数量由 `analysisModel.logicChain` 决定，不由模板决定。
- 推导环节标题必须是**本题专属任务**（「倒推·看清一次翻滚」「倒推·找周期规律」），禁止「推导环节」这类菜单名。
- **先结构后数据**：推导环节只建立关系和方法，具体数字留给「提取已知」（清点数据）之后的「列式计算」。这就是倒推式讲法——先想通要什么，再回头拿数据。

**难点识别——先自己把题做一遍**：

- 备课的第一动作不是读【分析】，而是**只看题干独立把题解一遍**，记录自己思维链里每个「必须想到才行」的瞬间——设参、作辅助线、换视角、逆用公式、构造等量……这些需要灵光的动作就是学生的难点。【分析】【详解】只给走通的路径，**不会告诉你哪一步反直觉**，难点必须靠自己的推演找出来，再与 `entryPoint.stuckPoint` 和各段 `difficulty` 互相印证。
- 一道题的难点往往**不止一个**：逻辑链上每个「凭什么想到」的转折都是独立难点，各自配自己的推导环节（或多个环节），不允许把几个难点塞进一段带过。

**难点展开——把「为什么这样做」摆在「怎么做」前面**：

- 复述答案是 20 分讲法的标志：直接宣布「作 PH 平行于 y 轴交 BC 于 H」而不讲为什么要作，学生只能背这一道题。难点环节的每个关键动作必须按「**动机 → 操作 → 回看**」展开：此刻我们缺什么 → 为什么想到用这个工具（别的路为什么走不通，`rejectedPaths` 的排除过程本身就是教学）→ 动手做 → 这一步换来了什么、离答案近了多少。
- 难点环节据此**成倍展开步数**：一个动机一拍、一个操作一拍、必要时回看再一拍，中间放互动让学生自己迈出关键一步；易段一两拍带过即可。展开的动机链写进该段 `approach`（不许只写操作）。

**步数由难度决定，没有上限**：

- 每段展开多深**只看它的 `difficulty` 星级**，不设任何步数预算字段：难度高的环节（≥5 星）通常 4 步起步；全题步数跟着逻辑链长度和难点数量走——难题二三十步是正常的，简单题短一些也是正常的。
- **禁止**为了控制总步数而合并难点、砍掉「为什么」；任何「凑成 8 步左右」的倾向都是错的，步数从来不是被优化的目标，学生想通才是。

### 4. 每个推导环节的三件配件

| 字段 | 写什么 | 作用 |
|------|--------|------|
| `difficulty` | 本段星级（1–8，与全题 `difficulty` 同尺度） | 难度透明：最难段提前「敲黑板」，最易段「送信心」；收尾拼装复盘的原料 |
| `linkBack` | 可选：本段复用了哪个旧知识/前面环节的结论 | 「半径处处相等——最早学的小知识点，今天在这里站岗」；让学生看到知识网 |
| `trap` | 可选：本段陷阱（出题人挖的坑） | fill 时做陷阱预警（措辞用 phrase-bank `trap.warn` 变体）；「掉过一次，考场上就绕着走了」 |

### 5. 互动题设计——`interactions[]`（备课时定题，上课时抛出）

真实课堂必须有互动。互动题在**备课阶段设计好**，写在所属环节的 `interactions[]`：

```json
"interactions": [
  {
    "form": "choice",
    "ask": "这 3 次翻滚中，当过旋转中心的顶点分别是谁？",
    "options": ["一直是同一个", "三个顶点轮流当"],
    "answer": "三个顶点轮流当",
    "tests": "发现周期结构——本段核心认知"
  }
]
```

**选型**（`form`）：

| 形式 | 何时用 | 对应 push |
|------|--------|-----------|
| `oral` 口答 | 概念复述、数值短答、占比判断 | `type: "oral"` |
| `choice` 选择 | 结构判断、易混淆二选一、陷阱辨析 | `type: "choice"` |
| `fill` 填空 | 算式补全、关键数值落笔 | `type: "fill"` |

**设计红线**：

- `tests` 必填：写清这道互动考察什么。**禁止无脑题**（1+1 式）；合格标准：答案要么是解锁下一步的钥匙（转了多少度？走了几段弧？），要么是本题知识点的直接运用（内角多少度？弧占几分之几？），要么需要稍想一下。
- 放在**认知关键点**上：学生自己答出这一问，这一步就是他自己想通的。
- 频率：每个推导环节原则上 ≥1 道；全题（example/practice 全量讲法）≥2 道。**审题环节永不设互动**；提取已知/列式等 outline 没覆盖的环节——fill 阶段从微步中取材补一道**过程级简单小问**，保证 **group 2..N** 每个大环节至少一道互动（见 fill-lesson-plan/step-splitting.md）。
- `answer` 按「意思相近即可」的口径写参考答案（fill 阶段落入 `userResponse`）。

## 三、收尾拼装——`closing`

最后一步算完，不能只报答案。用各环节的 `difficulty` 做**难度拼装复盘**：

| 字段 | 示例 |
|------|------|
| `recap` | 六星 ＝ 四星的旋转角 ＋ 三星的弧 ＋ 五星的规律 ＋ 二星的计算 |
| `takeaway` | 难题都是熟零件的新组装——这份底气带回家 |

让学生带走的是「难题可拆」的信念，不只是一个数。

## 四、屏幕极简原则——口播讲理，屏幕留证

课件屏幕上的**文字必须非常简洁，只留关键信息**；完整的讲述、解释、推理全部走 AI 老师的口播（`agent.description`）。学生的眼睛看骨架，耳朵听血肉。

| 去向 | 内容 |
|------|------|
| **屏幕**（push / problemBrief / 标注） | 算式、数据、短语级结论（「每次旋转 120°」「每周期 A 走 2 段弧」）、已知/求胶囊、互动题面与选项、图上数字标注 |
| **口播**（agent.description） | 为什么、怎么想到的、类比与联旧、陷阱解释、情绪与节奏、开场定位、收尾复盘 |

**硬性口径**：

- 屏幕文字是**短语，不是句子**：不写「因为…所以…」，不带完整主谓宾的解释句；一条卡片行的汉字 ≤ 24（算式不计），选项汉字 ≤ 12；题干置顶（开场 `region: "top"`）允许全文
- `problemBrief`：`known` 每条 ≤ 18 字（「两段 8 厘米的路」「一枚直径 4 厘米的游戏币」）、`ask` 一句话内、`key` 口诀级
- 结论上屏只上**结论本身**（「绿色段＝BC−r」），推导过程只在口播里
- 图上标注 = 数字/词语级（「8 厘米」「旋转中心」），不上整句
- **屏幕用数学符号，口播用汉字读法**：屏幕写 `△ABD` / `S△ABD` / `∠A` / `cm²、dm²`；「三角形」「平方厘米」等汉字读法只属于口播；题干原文按原题保留
- `positioning` / `entryPoint` / `closing` / `linkBack` / `trap` 的内容**只进口播，永不上屏**——唯一例外：「从哪入手」环节槽位必须落一张 `entryPoint.strategy` 的**范式级**短语卡（4–12 字；desc 废弃后环节槽内无兜底文字，每个环节至少一张卡）；陷阱可以在图上用高亮/闪烁提示位置，但不写解释文字

**正反例**：

- ✗ 屏幕卡片：「因为游戏币沿 AB 滚动时圆心到 AB 的距离永远等于半径，所以第一段轨迹与 AB 一样长，是 8 厘米」
- ✓ 口播讲上面整段道理；屏幕只推：「第一段＝AB＝8（cm）」

## 五、情绪与语气（fill 阶段执行）

- 发问要有热情和节奏感，带动课堂；揭晓后中立接续讲解，**不口播对/错**（见 reference.md「互动揭晓步口播」）。
- 最易的环节明说「这段是来送信心的」；最难的环节提前敲黑板、说清它值几颗星。
- 掉坑不羞辱：「这个坑就是给你挖的，今天掉过，考场上绕着走」。
- 所有情绪话术从 phrase-bank 取材变化，禁 `banned` 子串，禁逐字复制范例。

## 六、设计自检（备课完成前过一遍）

- [ ] 备课前**独立解过题**，难点清单来自自己的思维链，不是【分析】的转述
- [ ] 每个难点环节的 `approach` 写清了动机链（为什么这样做、别的路为什么不行），不是操作复述
- [ ] 展开深度与难度匹配：难段成倍展开，总步数没有为「凑短」被压缩
- [ ] 开场定位四项具体到本题，不是空话
- [ ] `entryPoint.strategy` 是解题思维范式（可迁移到同类题），不是操作步骤（无「先…再…」「分别…相加」「算占比」式列式链）；`stuckPoint` 真的是学生会卡的地方
- [ ] 每个推导环节有 `loop`（from→get），环节链能从已知一路推到最终答案
- [ ] 长逻辑链拆成了多轮推导，而不是塞进一个环节
- [ ] 每个推导环节标了 `difficulty`；陷阱都点名了；能联旧知识的地方写了 `linkBack`
- [ ] 互动题 ≥2 道、每道 `tests` 说得清考什么、没有无脑题
- [ ] `closing.recap` 的星级拼装与各环节 `difficulty` 对得上
- [ ] `problemBrief` 条目全是短语级；备课字段里没有为上屏而写的长句（口播讲理，屏幕留证）
