# 共用备课方法

## 输入

- 已确认的题干、答案和题目背景。
- 独立解题得到的思维链；原题分析与详解仅用于校对。
- 本题的学习位置、学生已有知识与典型误区。

## 输出

- 具体到本题的开场定位、切入点、教学阶段、难点说明、互动意图与收尾。
- 可落入当前 `outline.json` 的共用教学设计字段。

## 职责

- 只规定三类题共享的教学设计：为何学、从何切入、如何让学生想通、何处检查理解、最后带走什么。
- 使教学阶段服从真实推理链和难点，而不是服从固定步数或既有课件页面。
- 保持“口播讲理、屏幕留证”的教学取向；具体屏幕文字、标题、TTS 和交互承载方式属于后续 plan 阶段。

## 禁止项

- 不写计算题专属运算结构、纯文字/有图题专属关系模型、图形对象或图形动作。
- 不写布局、卡片、section、CSS、action、push、动画、坐标或代码。
- 不把 `beats`、`screenTitle` 等未实现字段当作当前 schema。

## 一、先解题，再备课

先只看题干完成求解，记录以下内容：

1. 已知、所求和隐藏限制；
2. 每一个“必须想到才走得通”的转折；
3. 容易但错误的直觉或路径；
4. 每个关键结论怎样验证或回看。

解析能校正答案，不能替代难点识别。一个推理链上的多个独立转折，应分别承担教学责任，不能因为答案写得短而合并抹平。

## 二、教学阶段先于呈现

outline 先形成大环节及其完整教学说明；它们可以是题目专属的一段教学话，不是屏幕标题。当前兼容基线中，例题和练题沿用：

```text
审题环节 → 从哪入手 → 题目专属推导环节 ×N → 提取已知 → 列式计算
```

- 审题大环节负责读清条件、所求与问句陷阱；当前规则中不设计互动。
- 切入大环节负责解释学生为什么卡住、高手先观察什么，以及可迁移的策略范式。
- 题目专属推导环节每段只承担一轮“依据 → 新认识/新量”；长链逐轮传递。
- “提取已知”和“列式计算”在结构已经想通后完成数据清点与结论拼装；短链题可合并。

`entryPoint.strategy` 是可迁移的观察角度，不是“先算什么再算什么”的操作清单。题内操作进入后续推导环节。屏幕标题、短语摘要和上屏证据一律留给 plan 提炼。

## 三、难点按动机、操作、回看设计

每个关键难点至少回答：

1. **动机**：此刻缺少什么；为什么这个工具、关系或变形值得尝试；哪些直觉路径不够。
2. **操作**：学生实际建立什么关系、执行什么变形或比较。
3. **回看**：这一步得到了什么；它怎样缩短与所求的距离；如何防止再次掉坑。

难点越高，动机、操作和回看越不能压缩。步数没有教学预算上限；易点可以简洁，难点不得为了凑短而跳过理由。

## 四、互动是认知检查，不是节奏装饰

- 互动放在学生答出后能解锁下一步、辨析误区或确认核心关系的位置。
- 每道题说明它检查什么；避免无需思考的口算或重复最终答案。
- 考点级互动在 outline 阶段确定；后续 plan 可为现有流程覆盖补过程级微问，但不得改变考点意图。
- 例题可设计本题快问快答，问题必须有唯一、具体的答案；练题和作业不复制该设计。

## 五、开场和收尾形成闭环

开场定位应具体说明：本题代表什么、能迁移的能力、必要时的考试语境，以及一个把注意力引向关键观察的钩子。不能只说“很重要”。

收尾不只报答案：回看各个难点如何组合成完整解法，并把本题策略提炼为学生下次可调用的判断。

## 六、当前字段与实现基线

当前生产基线把以上设计写入 `positioning`、`entryPoint`、`teachingStages[]`、`loop`、`difficulty`、`linkBack`、`trap`、`interactions[]` 和 `closing` 等字段。

计算仓还要求先写 `analysisModel`：`stem.known / ask / knowledge / key`、`logicChain[]`、`computeSteps[]`。`knowledge` 只供分析，绝不上屏。`problemBrief` 是独立备课字段，`known`、`ask` 必填、`key` 可选；它不进入 plan，也不生成 `readStem` 卡。

`lessonContext` 记录当前 slot、archetype、unitIntro、afterPlanId。example 的 `quickQASkeleton` 只问本题已出现的具体量、关系或中间量，写三到五项 `id / question / answer`；practice/homework 不写。practice 取 `slot: "afterExample"`，`afterPlanId` 指向紧邻例题。

当前互动写在推导 stage 的 `interactions[]`，每条包含 `form / ask / options（choice）/ answer / tests`，且 `tests` 必填；审题 stage 不设互动。`outlineStatus` 只取 `draft` 或 `approved`，现行 `plan:check` 通过后才能写为 `approved`。

后续可实现为更细的 `stages[]`、`beats[]` 与完整 `teachingNote`，以保留每个教学拍的动机、操作和回看；这不是当前 engine/schema 已支持的格式。
