# 文字与有图推理题教学逻辑

## 输入

- 纯文字题或有图题的题干、答案、条件、问题与原始解析。
- 独立解题得到的对象、关系、推导链、反例或常见误区。

## 输出

- 审题重点、关系识别、推导链、每段难点、误区和互动意图。
- 可映射到当前 `teachingStages[]` 的教学阶段设计；有图题再交由 `figure-addon.md` 补充图形教学职责。

## 职责

- 处理纯文字题与有图题共同的推理工作：从条件中抽取对象，建立关系，并把关系推到所求。
- 让学生理解“凭什么能推出”，而非只记结论、公式或图形直觉。
- 为每条关键关系明确来源、适用条件、用途与可能误读。

## 禁止项

- 不写计算题的运算呈现策略、公式排版或列式 UI。
- 不写图形坐标、对象定义、状态、动画、标注位置或图形代码。
- 不用“看图可知”“显然”替代关系依据。
- 不预设文字卡片、屏幕标题、TTS、action 或 push。

## 一、审题先建立对象与条件账本

把题干转化为可推理的账本：

1. 对象分别是什么，谁与谁相关；
2. 明示的数量、位置、顺序、范围或关系；
3. 所求是哪一个量、关系或判断；
4. 问句中最可能被误读的词；
5. 哪些背景信息不能当作条件使用。

审题不是照读题干。它的目标是让学生能区分“已知”“需要证明/求出”“暂时不能假定”的内容。

## 二、关系识别决定切入点

从对象账本中寻找能把已知接到未知的桥：

- 等量、等高、等面积、比例、对应、包含、互补、对称、平行、垂直或顺序关系；
- 定义、定理、公式的适用前提；
- 反求时可逆的关系；
- 多对象之间可传递的共同量。

切入点要说明学生为何会卡住、第一眼应该观察什么，以及为什么某条关系能作为桥。策略可以是“搭等量桥”“化未知为已知”“先看对应关系”“由条件反推”，但具体证明或求解动作进入推导阶段。

## 三、推导链逐段可追溯

每个推导环节只完成一轮有依据的变化：

```text
条件/已得结论
→ 关系或规则
→ 新结论
→ 新结论如何成为下一轮依据
```

- 在建立关键关系、切换模型、使用不同定义/公式族、进行反推或出现独立难点时拆段。
- 上一段得到的新结论必须说明如何进入下一段，避免“因此”跳跃。
- 同一目标、同一依据的微小表述变化可以合并；不同理由不能合并成一句。
- 对每个关键结论留出回看：它验证了什么、排除了什么误解、离所求还差什么。

## 四、误区和互动围绕推理关口

典型误区包括：把图形外观当条件、遗漏限定词、混淆对应对象、错误传递等量、倒置因果、在反求中直接套正向公式。

互动应让学生在关键关系处作出可判断的选择：选哪条依据、某个量能否传递、下一步应证明什么、一个结论的适用条件是否满足。不要把互动降为复述题干或猜最终答案。

有图题中，关系的教学解释仍在这里完成；“图要帮助学生看清什么”再由 [figure-addon.md](figure-addon.md) 记录，不让视觉效果替代论证。

## 五、当前字段与实现基线
