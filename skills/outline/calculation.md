# 计算题教学逻辑

## 输入

- 纯计算题的题干、答案、可接受的等价解法和原始解析。
- 独立完成的运算过程、关键变形、易错点与可行验算。

## 输出

- 运算结构、切入策略、演算链、关键中间式、验算点与互动意图。
- 对“最终列式是否值得设计挖空”的教学判断；具体空格、答案和显示位置留给后续阶段。

## 当前 calculation outline 兼容

现行 outline 先用 `analysisModel` 固化独立求解：`stem`（`known`、`ask`、内部 `knowledge`、`key`）、`logicChain[]` 与 `computeSteps[]`；再从题干抽取 `problemBrief.known / ask / key`。二者都是备课数据，`knowledge`、`problemBrief` 不得进入 plan 或屏幕。

- `lessonContext.archetype` 仅为讲法提示：`directFormula` 只用于同一公式族、`logicChain` 不超过两层且无跨关系/反求；等量桥、逆用、两个公式族或更长链选 `relationBridge`，其余按拆分、周期、裂项等真实结构选择。
- `teachingStages[]` 的推导段由 `logicChain` 切分，每段有题内唯一 slug、goal、approach、`loop.from → loop.get`、difficulty，前段 get 进入后段 from；`tests` 是每个互动的必填考查说明。
- example 必写三到五条 `quickQASkeleton`，practice 不写；practice 的 `lessonContext.slot` 为 `afterExample`，`afterPlanId` 指向例题。
- 初稿为 `outlineStatus: "draft"`；仅通过当前 `npm run plan:check` 后才标为 `"approved"`。这不是目标 schema 的验证。

## 职责

- 决定计算题应让学生看懂的数量、等式或代数结构，而不只是复述算完的步骤。
- 将“为何做这一步”与“做完得到什么”写进演算链，识别需要单独教学的变形和中间量。
- 区分列式挖空的教学价值与它的具体 UI 实现。

## 禁止项

- 不写 `top-split`、`.calc-*`、`retainPush`、公式 fit、滚动、卡片、布局或最终公式排版。
- 不写 action、push、TTS、具体填空 parts、答案揭晓或运行时交互。
- 不把“能填一个空”误判成“有教学价值的列式挖空”。

## 一、先识别运算结构

不要先按算符逐行朗读。先判断本题真正需要学生识别的结构，例如：

- 运算顺序、括号或符号的约束；
- 同类项、因式、分母、幂或根式的可处理结构；
- 通项、相邻项、分组、抵消或周期；
- 已知量与未知量之间的等式、比例或反求关系；
- 可拆分、可合并、可逆用的数量关系。

结构是切入点的依据。若只是同一公式族、逻辑链很短且无反求或跨关系传递，才适合直接代入；存在变形、分层计算、反求或多种关系时，应显式设计对应的推导环节。

## 二、策略必须解释“为什么”

策略是可迁移的判断，不是机械的演算顺序。可采用“先统一结构”“拆整留分”“裂项相消”“逆向还原”“化未知为已知”等表述；随后再在演算链中写具体操作。

为每一个关键策略说明：

1. 当前表达式或数量关系的障碍；
2. 选择该变形、拆分或顺序的理由；
3. 变形后出现的可计算结构；
4. 可能混淆的符号、范围或等价条件。

## 三、演算链按教学依赖拆分

演算链不是最终答案的长等式，而是一系列有依赖关系的理解：

```text
识别条件/结构
→ 选择策略
→ 建立或变形关键式
→ 得到中间量或可计算形式
→ 代入、运算、化简
→ 结果检查
```

- 一个中间式应单独保留，当它改变了结构、产生后续必需量、暴露易错点，或是学生必须学会复用的动作。
- 连续的纯机械算术可合并，但不能吞掉符号变化、等价变形、约分条件或进位借位等理解节点。
- 记录每个中间量的来源和用途；只有知道其用途，学生才不会把它当作多余步骤。
- 最后设计合理性或逆向验算：单位、符号、数量级、代回条件、特例或等式两边一致性。

## 四、是否需要列式挖空

这是 outline 的教学判断，不是 UI 决定。仅当以下条件同时满足时，标记“建议后续设计列式挖空”：

1. 所需的量和关系已经在前文明确；
2. 学生应练习的是把这些量组织为一个完整、唯一、可读的表达式；
3. 该表达式可在一次作答中完成，不依赖尚未说明的多步推导；
4. 填出表达式比直接报数更能检验策略或关系。

以下情况不建议强行挖空：

- 表达式可有多种同样合理的写法，难以定义单一答案；
- 学生仍需先发现关系、选公式或完成多步变形；
- 空格只是在机械补一个数字，不能验证理解；
- 关键困难在结构识别而不在最终列式。

可在当前兼容的教学描述中记录该意图；`interactionIntent: { kind: "formula-completion" }` 尚未由当前 engine/schema 普遍支持。具体填空格式、答案判定和呈现位置以后续 plan 与 profile 规则为准。
