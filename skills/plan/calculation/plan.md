# 计算 Profile：教学拍到讲法与当前 action 骨架

**职责：** 将计算题的 outline 教学拍折叠为计算讲法，同时保留逐拍标题、TTS、互动和来源。  
**输入：** 共用 plan 规则、计算题 outline 的结构识别、演算链、关键中间式和互动意图。  
**输出：** 适合 calculation profile 的目标 plan steps。  
**禁止项：** 不定义 `.calc-*`、容器参数、公式 fit 或当前 action 名；不把 outline 环节机械地一对一变成 UI action。

> **当前生产优先：** 本节的 action、短 id、push 与布局规则是计算题必须遵守的现行契约。`screenTitle`、`source`、`profileView` 与统一 `renderProfile` 仍是目标字段，**不得**写入当前 production JSON。

## 当前 calculation action 骨架

```text
{前缀}_开始 → {前缀}_要点_起 / 条* / 可选问答 → {前缀}_详解_起
           → {前缀}_详解_步* → {前缀}_答案
```

- 前缀使用例题 `例_`、练题 `练_`；多小题按现有课程约定使用 `例1_`、`例2_` 等。
- 开场只在 `top` 展示题干与原题展开式，不出现答案或互动。
- outline 的 `read-problem + entry-point` 在 fill 时折叠为一次【要点】，不是逐阶段 action；“提取已知 + 列式计算”并入详解末段。
- 要点阶段最多四拍（`起`、条、可选问/答均计入）；仅左栏，最多两条 `calc-key-list`。严禁命名 `_要点_审题`、`_要点_所求`、`_要点_策略`、`_要点_入手`（以及 `_要点_分析`）。
- `详解_起` 是切换拍：只 push `right` 的精简 `calc-key-pin`（必要时加 `calc-key-tex`），不得写 `retainPush`，不得同拍推 left。
- 每个 `详解_步*` 以一组 `calc-solve-note + calc-solve-step` 展开一个认知微步；`loop.get` 是终点，不得整块倾倒。首个详解步不重复推【详解】标签。
- 答案仅在最后用 `calc-answer--final` 显示；此前保留所需演算链。不得在题干、要点或详解前段预告最终值。

## 教学映射

- 开场：兑现定位并显示原题，不展示完整解法或答案。
- 审题和入手：折叠为有限的“要点”，只保留解题结构与策略，不拆成多个文字题式 UI 环节。
- 推导：每个中间式、代入或变形仍为独立微步；每拍保留自然标题、TTS 和屏幕证据。
- 最终量：若 outline 指定 `formula-completion` 且满足共用互动规则，在最终计算前插入列式挖空。
- 答案：晚出，兑现收尾回看而非仅显示得数。

## 互动

- 选择最能暴露结构判断、变形理由或最终列式的一个关键节点，避免在开场提问。
- 计算 profile 可以压缩 UI 段数，不能删除该互动的来源、TTS、标题或标准答案。
- 列式挖空由 outline 决定是否需要；本 profile 只决定它进入要点、详解或答案之前的哪一拍。
