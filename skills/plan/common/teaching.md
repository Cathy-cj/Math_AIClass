# 共用讲解与拆拍规则（目标 SOP）

**职责：** 规定如何把 outline 的完整教学话转为逐拍讲解节奏。  
**输入：** outline 的 stage、beat、`teachingNote`、难点、互动意图和收尾。  
**输出：** 每拍可讲、可显示、可验证的 plan step。  
**禁止项：** 不定义 TTS 读法、profile UI、CSS、图形动作协议或运行时 action 映射。

> `teachingNote`、beat 和逐拍来源均为目标字段；当前生产仍以 `teachingStages[]`、`loop`、`difficulty` 等字段为准。

## 从 outline 到 plan

- outline 决定教什么：每个大环节写完整教学说明，说明学生此刻为何要做、怎样做、理解什么。
- plan 决定每拍怎样讲与怎样显示：每个 step 必须落下 **标题、TTS、互动（若有）、上屏证据**，并追溯到对应大环节。
- 所有标题都由 plan 从完整教学说明提炼；outline 不预写固定或缩略的屏幕标题。

## 拆拍

1. 一拍只完成一个认知 beat；中间量、代入、变形、比较和结论分别成拍。
2. `loop.get` 或最终结论是目标，不可整块直接上屏。
3. 难点至少展开为“动机 → 操作 → 回看”：先解释缺什么或为何选此路，再做操作，最后连回已有结论。
4. 逻辑链、难点和互动目的改变时拆拍；易段可以短，禁止为了凑固定步数合并难点。
5. 屏幕留可抄的证据，口播解释理由；不要把解释长句搬上屏。

## 当前兼容的微步与累积

当前 production plan 尚未使用目标 `beats[]`，但必须以同样粒度展开 `steps[]`：每个中间量、代入、变形、比较与结论各是一拍；`loop.get` 只能作为阶段目的，不能在一拍中连同全部推导一次展示。

- 新的板书/演算证据向下追加；每个新增语义行使用新的 `replaceKey`。
- 只有确实改写同一个既有槽位时才能复用 `replaceKey`；不能借它覆盖前一拍已讲的演算。
- 当前 calculation 还须同时遵守 `retainPush` 的容器保留语义，详见 `plan/calculation/presentation.md`；它不能替代上述逐步展开。

这些是现行 `steps[]` / `push` 约束；`beatId`、`source`、`screenEvidence` 仍属于目标 schema，不能填入当前 JSON。

## 开场与收尾

- 开场兑现 outline 的定位：引子、题型代表性和可迁移方法；不要直接开始演算。
- 收尾先回看本题链条和关键陷阱，再给出可迁移 takeaway；最终答案不是唯一收尾内容。
